# IP Checker Website (ZeroTier Inside Docker)

Простой веб-сайт на Python (Flask), отображающий IP-адреса пользователя.

**Конфигурация:**
*   **ZeroTier:** Работает **внутри** контейнера.
*   **Доступ:** Только через сеть ZeroTier (безопасно).
*   **Порты хоста:** Не используются (нет конфликтов с nginx/apache).

## 1. Настройка

1.  Откройте `docker-compose.yml`.
2.  Найдите строку `ZT_NETWORK_ID=...` и вставьте туда **ID вашей сети** (16 символов, из панели ZeroTier).

## 2. Запуск

```bash
docker-compose down -v
docker-compose up -d --build
```

## 3. Авторизация в ZeroTier

Поскольку ZeroTier теперь работает внутри контейнера, это **новое устройство** для вашей сети.

1.  Посмотрите логи, чтобы узнать Node ID:
    ```bash
    docker logs ip_checker_site
    ```
    Вы увидите что-то вроде:
    ```
    ZeroTier Node ID:
    a1b2c3d4e5
    ```

2.  Зайдите в панель управления ZeroTier (my.zerotier.com).
3.  Найдите устройство с этим ID и поставьте галочку **Auth**.
4.  Подождите пару минут и обновите страницу. Устройству будет назначен IP (например, `172.25.28.55`).

## 4. Доступ к сайту

Теперь сайт доступен по **этому новому IP**, который ZeroTier выдал контейнеру.
👉 `http://172.25.28.55` (пример)

## 5. Доменное имя внутри ZTNet

Поднимать DNS можно на любом узле внутри вашей сети ZeroTier — не обязательно там, где установлен ZTNet (контроллер). Сам ZTNet лишь раздаёт клиентам настройки “какой DNS использовать” и “какой search domain”.

В этом репозитории добавлен DNS-сервис `ip_checker_dns` (CoreDNS), который работает в той же сетевой неймспейсе, что и контейнер `ip_checker_site`, то есть слушает DNS на ZeroTier-IP контейнера.

- Имя: `ipchecker.home.arpa`
- DNS: `172.25.27.64:53`

Чтобы это заработало:
- В ZTNet в разделе **DNS** укажите:
  - **Поисковый домен**: `home.arpa`
  - **Адрес сервера**: `172.25.27.64`
- Перезапустите контейнеры: `docker-compose up -d --build`
- На клиенте проверьте: `nslookup ipchecker.home.arpa 172.25.27.64`

Если ZeroTier-IP вашего контейнера изменится, обновите IP в файле `dns/Corefile` и перезапустите: `docker-compose up -d --build`.

## 5. Устранение ошибок (Port 80 failed)

Если вы раскомментируете `ports: - "80:80"` в файле `docker-compose.yml` и получите ошибку:
`Bind for 0.0.0.0:80 failed: port is already allocated`

Это значит, что на вашем сервере уже что-то работает на 80 порту (Nginx, Apache или наш скрипт `run_native.sh`).

Чтобы исправить это, выполните:
```bash
chmod +x kill_port_80.sh
sudo ./kill_port_80.sh
```
А затем перезапустите контейнер.
