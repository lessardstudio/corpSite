# IP Checker Website с интеграцией 3x-ui

Простой веб-сайт на Python (Flask), отображающий IP-адреса пользователя. Развернут в изолированной Docker-сети со статическим IP `10.5.0.2`.

> **Обновление:** IP-адрес был изменен с `10.0.0.2` на `10.5.0.2`, чтобы избежать конфликтов "Address already in use" на VPS серверах, где подсеть `10.0.0.0/24` часто используется провайдером или VPN-интерфейсами.

## Структура проекта

* `app.py`: Flask приложение.
* `Dockerfile`: Конфигурация образа.
* `docker-compose.yml`: Конфигурация сети и контейнера.
* `deploy.sh`: Скрипт для автоматического развертывания и очистки старых контейнеров.

## 1. Развертывание (Docker)

### Предварительные требования
* Docker и Docker Compose должны быть установлены.

### Быстрый запуск (Linux/Bash)

```bash
chmod +x deploy.sh
./deploy.sh
```

### Ручной запуск

1. Перейдите в папку проекта:
   ```bash
   cd c:\Users\User\Desktop\corpSite
   ```

2. Очистите предыдущие запуски (важно при смене сети):
   ```bash
   docker-compose down -v
   ```

3. Запустите контейнер:
   ```bash
   docker-compose up -d --build
   ```

4. Проверьте статус:
   ```bash
   docker ps
   ```

## 2. Настройка сети

В `docker-compose.yml` настроена сеть `private_net` с подсетью `10.5.0.0/24`.
* **IP Контейнера:** `10.5.0.2`
* **Шлюз:** `10.5.0.1`

## 3. Интеграция с 3x-ui (Outbound / Routing)

Чтобы пользователи вашего VPN (Xray/3x-ui) могли попадать на этот сайт по IP `10.5.0.2`, нужно настроить маршрутизацию.

**Предполагается, что 3x-ui также запущен в Docker или имеет доступ к сети хоста Docker.**

### Вариант А: Если 3x-ui в том же Docker Compose (рекомендуется)
Добавьте контейнер 3x-ui в ту же сеть `private_net` в вашем docker-compose файле.

### Вариант Б: Настройка Routing Rules (Xray Config)

В панели 3x-ui перейдите в **Settings -> Xray Configuration -> Routing Rules**.

Добавьте правило:

```json
{
  "routing": {
    "rules": [
      {
        "type": "field",
        "ip": ["10.5.0.2"],
        "outboundTag": "direct"
      }
    ]
  }
}
```

## 4. Устранение неполадок

Если вы видите ошибку `Address already in use`:
1. Убедитесь, что вы выполнили `docker-compose down -v` для удаления старой сети.
2. Проверьте, не занят ли IP адрес другими сервисами.
3. Попробуйте выполнить `docker network prune`.
